Reptar provides first-class primitives to build ChatGPT-style applications, autonomous AI agents (like `pi` and `fx`), and real-time streaming interfaces.

Because Reptar already maintains route metadata and `Rule<T>` validator constraints, your existing backend routes can be invoked directly by AI agents with zero duplicate schema maintenance.

---

## 1. Route Tool Definition (`.AsAiTool()`)

Register your routes normally with typed input validators, and designate them as AI tools using `.AsAiTool()`:

```csharp
app.Post("/api/projects/:projectId/tasks", TaskValidator, async (ctx, input) =>
{
    var projectId = ctx.Req.Param("projectId");
    var task = new TaskItem(Ids.New("tsk"), projectId, input.Title, input.Priority, "open");
    await ctx.Db.InsertAsync(Schema.Tasks, task);
    return ctx.Json(task, 201);
})
    .WithSummary("Create a task")
    .AsAiTool("create_task", "Creates a new task in the specified project");
```

- **Path Parameters**: Path variables like `:projectId` are automatically extracted and merged into the tool's required JSON schema.
- **Validation Constraints**: `Rule<T>` constraints (`.Min()`, `.Max()`, `.Email()`) are mapped directly into JSON Schema validation rules.

## 2. Generating Tool Schemas (`app.GetAiTools()`)

Export tools in standard schema formats for **OpenAI, Anthropic Claude, or Google Gemini**. The safe default is **explicit opt-in**: only routes marked with `.AsAiTool(...)` are exported. Pass `onlyExplicit: false` if you deliberately want every HTTP route exposed to the model.

```csharp
// OpenAI function calling format (explicit .AsAiTool routes only)
var openAiTools = app.GetAiTools(AiToolFormat.OpenAi);

// Anthropic Claude format
var claudeTools = app.GetAiTools(AiToolFormat.Anthropic);

// Google Gemini format
var geminiTools = app.GetAiTools(AiToolFormat.Gemini);

// Opt-in: expose every route (auth mutations, admin deletes, ...)
var allRoutes = app.GetAiTools(AiToolFormat.OpenAi, onlyExplicit: false);
```

### Auto-Generated Schema Example

When formatted for OpenAI, Reptar outputs:

```json
[
  {
    "type": "function",
    "function": {
      "name": "create_task",
      "description": "Creates a new task in the specified project",
      "parameters": {
        "type": "object",
        "properties": {
          "projectId": {
            "type": "string",
            "description": "Route parameter projectId"
          },
          "title": { "type": "string", "minLength": 3, "maxLength": 50 },
          "priority": { "type": "integer", "minimum": 1, "maximum": 5 }
        },
        "required": ["projectId", "title", "priority"]
      }
    }
  }
]
```

### Expose Tool Definitions Over HTTP

Serve the tool schemas for ChatGPT plugins, Claude tool-use, or external agents in one line:

```csharp
app.MapAiTools("/api/ai/tools", AiToolFormat.OpenAi);
```

## 3. In-Process Tool Execution (`app.ExecuteAiToolAsync()`)

When an LLM model issues a tool call, execute it **in-process with zero network hops**:

```csharp
var result = await app.ExecuteAiToolAsync("create_task", toolCall.ArgumentsJson, ctx);
```

### Self-Healing Agent Validation

If the model hallucinates invalid arguments (e.g. an empty title or an invalid priority number), `result.ToLlmResponse()` automatically returns the exact validation errors so the model can self-correct:

```
Error (validation_error): Validation failed. Issues: title: Must be at least 3 characters, priority: Must be at most 5
```

When the LLM receives this string, modern reasoning models (Claude 3.5 Sonnet, GPT-4o, Gemini 1.5 Pro) immediately fix their parameters and retry.

## 4. Autonomous Loop & Evaluators (`LoopRunner`)

For production agents that iterate toward a goal, Reptar provides **`LoopRunner`** and **`LoopEvaluator`**. An autonomous loop re-invokes the agent with structured feedback until an evaluator signals completion, with a hard `MaxIterations` safety cap:

```csharp
var todos = TodoModule.Create("session_123");
var todoTools = AgentModuleComposition.ComposeTools(todos);
var todoExecutor = AgentModuleComposition.ComposeExecutor(null, todos);

var evaluator = LoopEvaluators.TodoCompletion("session_123", todos);

var result = await LoopRunner.RunAsync(
    history,
    llmClient.StreamAsync,
    todoExecutor,
    todoTools,
    evaluator,
    maxIterations: 10,
    model: "claude-3-5-sonnet");

// Loop terminates deterministically with result.StopReason:
Console.WriteLine($"Finished in {result.Iterations} iterations: {result.StopReason}");
```

Available evaluators:

- `LoopEvaluators.TodoCompletion(sessionId, todos)`: Continues providing feedback until all todo items are marked complete.
- `LoopEvaluators.CompletionMarker(marker)`: Stops when a designated sentinel token (e.g. `[TASK_COMPLETE]`) is output.
- `LoopEvaluators.Delegate(func)`: Custom host-defined evaluation predicate.

## 5. Structured Output & Self-Healing Schemas (`StructuredOutput`)

Extract strongly-typed C# records from unstructured LLM responses without runtime reflection:

```csharp
public record ExtractedTask(string Title, int Priority, string[] Tags);

var candidate = await StructuredOutput.ExtractAsync<ExtractedTask>(
    llmClient,
    prompt: "Extract the task details from: Ship Reptar v1 with high priority (5) and tags backend, wasm",
    cancellationToken: ctx.CancellationToken);

if (candidate.Success)
{
    var task = candidate.Value;
    Console.WriteLine($"Extracted: {task.Title} (Priority {task.Priority})");
}
```

If the LLM emits malformed JSON or omits required fields, `StructuredOutput` automatically feeds the exact JSON Schema validation error back to the model in a follow-up turn to repair the payload.

## 6. Human-in-the-Loop & Approval Rules (`ToolApproval`)

Govern agent behavior by intercepting risky tool calls before execution:

```csharp
var rules = new ToolApprovalPolicyBuilder()
    .RequireApproval("rm", "drop_table", "deploy_production")
    .AllowWithoutPrompt("read_file", "list_dir", "db_status")
    .Build();

// Intercepts tool execution when approval is required
var approvedExecutor = ToolApproval.Wrap(toolExecutor, rules, onApprovalRequired: async request =>
{
    Console.WriteLine($"[APPROVAL REQUIRED] Agent wants to call {request.ToolName} with {request.ArgsJson}");
    return await PromptHumanOperatorAsync(request);
});
```

## 7. Zero-Copy LLM Streaming (`ctx.StreamLlmAsync()`)

For ChatGPT-style web interfaces and mobile apps (React Native / Expo), stream tokens down via Server-Sent Events (SSE) with instant cancellation:

```csharp
app.Post("/api/chat", async ctx =>
{
    var prompt = ctx.Req.QueryValue("message", defaultValue: "");
    var tokenStream = OpenAiClient.StreamTokensAsync(prompt, ctx.CancellationToken);

    // Pipes tokens directly through Kestrel's PipeWriter or Cloudflare's TransformStream:
    return ctx.StreamLlmAsync(tokenStream);
});
```

- **Instant Disconnect Cleanup**: If the user clicks "Stop Generating" or closes their app, `ctx.CancellationToken` aborts immediately, stopping upstream LLM billing.
- **Done Sentinel**: Emits `data: [DONE]\n\n` automatically when the token stream finishes.

## 8. Coding Agent Tooling: MCP Server, CLI Inspection & Two-Layer Agent Docs

Reptar is designed from the ground up to be operated by AI coding agents (Claude Code, Cursor, Antigravity, Windsurf) with zero guesswork:

### Built-In MCP Server (`bun reptar mcp`)

Expose your project's routes, compiler-backed `TableDef` schemas, schema drift plan, and codegen tools over Model Context Protocol (stdio JSON-RPC 2.0):

```bash
bun reptar mcp
```

Published MCP tools:

- `reptar_inspect` — Full project topology (routes, compiler-extracted `TableDef` columns, `[ReptarEntity]` records, migrations, and environment bindings).
- `reptar_doctor` — Verifies .NET SDK, Bun, SQLite connectivity, `AGENTS.md` pointer block, and RPC contract freshness.
- `reptar_db_plan` — Compares compiled `TableDef` schemas (`--schema`) against the active SQLite database and returns pending DDL statements.
- `reptar_db_generate` — Generates a timestamped `.sql` migration file from the current schema diff.
- `reptar_db_migrate` — Transactionally applies pending `.sql` migrations.
- `reptar_codegen` — Regenerates `@reptar/client` TypeScript RPC contracts and OpenAPI 3.1 specs.

### Machine-Readable CLI Flags (`--json`)

Every inspection command supports deterministic `--json` output for agent tool calls:

```bash
bun reptar inspect --json
bun reptar doctor --json
bun reptar db plan --json
```

### Two-Layer Agent Documentation (`@reptar/client`)

Reptar uses a non-destructive two-layer documentation pattern so upgrading `@reptar/client` automatically updates your agent's framework knowledge without cluttering your repository root:

1. **Version-Pinned Manual in `node_modules`**: `@reptar/client` ships `node_modules/@reptar/client/AGENTS.md`, `node_modules/@reptar/client/llms.txt`, and `node_modules/@reptar/client/skills/reptar/SKILL.md`.
2. **Non-Destructive Managed Pointer Block**: Running `bun create reptar` or `bun reptar init` (or `bun reptar doctor --fix`) appends or updates a compact `<!-- reptar:agents:start --> ... <!-- reptar:agents:end -->` pointer block inside your root `AGENTS.md` while preserving all existing team/linter rules.
