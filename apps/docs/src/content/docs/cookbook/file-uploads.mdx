---
title: File Uploads & Object Storage
description: Validate uploads with magic bytes, stream them to R2/S3/local disk, and serve them with ETags, byte ranges, and presigned URLs.
---

Reptar's `c.Storage` is a small, provider-agnostic object store. The same C# code
runs against Cloudflare R2 on Workers, S3-compatible storage on Native AOT, and
local disk during development.

---

## 1. Configure storage

```csharp
var app = ReptarApp.Create(new ReptarConfig
{
#if NETWASM
    Storage = Storage.R2(),                 // binds to env.BUCKET
#else
    Storage = Storage.Disk("./uploads"),    // local disk
    // Storage = Storage.S3(new S3StorageOptions { ... });
#endif
});
```

All providers share the same core operations:

| Operation | What it does |
| :-- | :-- |
| `PutAsync(key, bytes, contentType)` | Write an object. |
| `PutAsync(key, stream, contentType)` | Stream an object; S3/R2 use multipart with a configurable part size. |
| `GetAsync(key)` | Read the full object, or `null` when missing. |
| `ExistsAsync(key)` / `DeleteAsync(key)` | Cheap existence check / delete. |
| `DeleteManyAsync(keys)` | Batch delete (native `DeleteObjects` on S3, array delete on R2). |
| `CopyAsync(source, destination)` | Server-side copy on S3, file copy locally. |
| `MoveAsync(source, destination)` | Copy + delete, with source cleanup. |
| `HeadAsync(key)` | Size, content type, ETag, last-modified, user metadata. |
| `GetRangeAsync(key, offset, length)` | Read a byte range without downloading the object. |
| `ListAsync(options)` | Prefix listing with an opaque cursor. |
| `PresignPutAsync(...)` | Direct browser → R2/S3 upload URL. |
| `PresignGetAsync(...)` | Direct browser → R2/S3 download URL. |
| `PublicUrl(key)` | CDN/custom-domain URL when configured. |

Use `c.Storage.Capabilities` to branch portably:

```csharp
if (c.Storage.Capabilities.Has(StorageFeatures.PresignUpload))
{
    var upload = await c.Storage.PresignPutAsync(
        $"avatars/{c.User!.Id}.png",
        "image/png",
        TimeSpan.FromMinutes(10));
}
```

## 2. Validate and upload

Never trust the client `Content-Type`. `Files.Check` sniffs magic bytes, enforces
a size limit, and accepts MIME families such as `image/*`:

```csharp
app.Post("/api/avatar", Auth.RequireUser, async ctx =>
{
    var form = ctx.Req.Form;
    var file = form?.File("avatar") ?? (form is { Files.Count: > 0 } ? form.Files[0] : null);

    var check = Files.Check(
        file?.Data ?? ctx.Req.Body,
        maxBytes: 5 * 1024 * 1024,
        "image/*");

    if (!check.Ok)
        return check.ToError(ctx); // 400 / 413 / 415 with a standard error envelope

    var key = $"avatars/{ctx.User!.Id}.{check.Extension}";

    await ctx.Storage.PutAsync(
        key,
        check.Data,
        check.ContentType,
        new StoragePutOptions
        {
            // Fail with 412 instead of silently replacing an existing object.
            Overwrite = true,
            CacheControl = "public, max-age=31536000, immutable",
            Metadata = new Dictionary<string, string>
            {
                ["uploaded-by"] = ctx.User.Id,
            },
        });

    return ctx.Json(new { key, url = $"/files/{key}" }, 201);
});
```

`StorageKey` normalizes every provider key and rejects traversal, control
characters, empty segments, and over-long segments before any I/O happens.

## 3. Serve with ETags, 304s, and byte ranges

`c.File(key)` is the one-liner file server. It uses `HeadAsync` for metadata,
emits `ETag` / `Last-Modified` / `Cache-Control`, answers `If-None-Match` with
`304`, and answers `Range` with `206 Partial Content`. `HEAD` is handled
automatically by the router.

```csharp
app.Get("/files/:key", ctx =>
    ctx.File(ctx.Req.Param("key")!, new StorageFileOptions
    {
        Immutable = true, // public, max-age=31536000, immutable
        Headers = new Dictionary<string, string>
        {
            ["X-Content-Type-Options"] = "nosniff",
            ["Content-Security-Policy"] = "default-src 'none'; sandbox",
        },
    }))
    .Produces(200)
    .Produces(206)
    .Produces(304);
```

Downloads use `c.Attachment`:

```csharp
app.Get("/download/:key", ctx => ctx.Attachment(ctx.Param("key")!));
```

`c.File` defaults to `Cache-Control: private, max-age=0, must-revalidate` so a
private object is never stored by a shared cache. Public assets opt in with
`Immutable = true` or an explicit `CacheControl`.

If a provider only implements the four core methods, `c.File` falls back to
`GetAsync` and still works. Range requests are served from memory in that case;
providers with `StorageFeatures.RangeReads` avoid the full download.

### Nested keys with wildcard routes

A `:key` route param only matches one path segment. For nested keys, use a named
catch-all (`*path`). Static and single-segment routes still take precedence:

```csharp
app.Get("/files/*path", ctx => ctx.File(ctx.Param("path")!));
// GET /files/avatars/user_1/photo.png -> key "avatars/user_1/photo.png"

app.Get("/files/health", ctx => ctx.Text("static wins"));
app.Get("/files/:id", ctx => ctx.Text("one segment wins"));
```

The generated client exposes catch-all routes under their literal segment key:

```ts
await client.files["*path"]({ param: { path: "avatars/user_1/photo.png" } });
```

The client preserves `/` separators while percent-encoding each segment.
WebSocket routes support the same named catch-all syntax:

```csharp
app.OnWebSocket("/ws/files/*path", new WebSocketHandlers
{
    Message = (connection, message) =>
        connection.SendAsync($"watching {connection.Ctx.Param("path")}"),
});
```

## 4. Copy, move, and bulk delete

```csharp
var copied = await ctx.Storage.CopyAsync(
    "avatars/source.png",
    "avatars/copied.png",
    new StorageCopyOptions
    {
        Overwrite = false,          // 412 when the destination exists
        PreserveMetadata = true,    // content type, cache control, user metadata
    });

var moved = await ctx.Storage.MoveAsync("drafts/a.png", "published/a.png");
await ctx.Storage.DeleteManyAsync(["drafts/b.png", "drafts/c.png"]);
```

S3 uses a native server-side copy (`x-amz-copy-source`) and the `DeleteObjects`
batch endpoint. R2 uses an array delete. Local disk uses `File.Copy` /
`File.Move` and moves the metadata sidecar.

Copies preserve `Content-Type`, `Cache-Control`, `Content-Disposition`,
`Content-Encoding`, `Content-Language`, and user metadata by default. Set
`PreserveMetadata = false` or pass overrides to replace them. `ctx.File` serves
the stored `Content-Encoding` / `Content-Language` / `Content-Disposition`
headers automatically.

## 5. Direct uploads and downloads

For large files, skip the Worker/API entirely. Presign a URL and let the browser
talk to R2/S3:

```csharp
app.Post("/api/uploads/presign", Auth.RequireUser, async ctx =>
{
    var key = $"uploads/{ctx.User!.Id}/{Ids.New("file")}";
    var upload = await ctx.Storage.PresignPutAsync(
        key,
        "application/octet-stream",
        TimeSpan.FromMinutes(10));

    return ctx.Json(new
    {
        upload.Url,
        upload.Method,
        upload.Headers,
        upload.ExpiresInSeconds,
    });
});
```

Presigned downloads can override the response headers without mutating the
stored object:

```csharp
var download = await ctx.Storage.PresignGetAsync(
    key,
    TimeSpan.FromMinutes(5),
    new PresignDownloadOptions
    {
        FileName = "report.pdf",
        ContentType = "application/pdf",
        CacheControl = "private, max-age=60",
    });
```

## 6. Streaming and multipart uploads

`PutAsync(key, stream, contentType)` avoids buffering the whole object on
providers that support streaming. S3 and R2 switch to multipart automatically
above the configured part size (8 MiB by default) and abort the upload if any
part fails:

```csharp
await using var file = File.OpenRead("large-video.mp4");
await ctx.Storage.PutAsync(
    "videos/large-video.mp4",
    file,
    "video/mp4",
    new StoragePutOptions
    {
        CacheControl = "public, max-age=31536000, immutable",
    });
```

Check capabilities before relying on the optimized path:

```csharp
if (ctx.Storage.Capabilities.Has(StorageFeatures.MultipartUpload))
{
    // S3/R2: bounded-memory parts.
}
```

Tune the part size per provider:

```csharp
Storage = Storage.S3(new S3StorageOptions
{
    Endpoint = "https://acc123.r2.cloudflarestorage.com",
    Bucket = "media",
    AccessKeyId = "...",
    SecretAccessKey = "...",
    MultipartPartSizeBytes = 16 * 1024 * 1024,
});

Storage = Storage.R2(new R2StorageOptions
{
    MultipartPartSizeBytes = 16 * 1024 * 1024,
});
```

Values below 5 MiB are clamped to the provider minimum.

### Streaming the request body

By default the framework buffers the request body so `ctx.Req.Body`,
`ctx.Req.Form`, and `ctx.BindJsonAsync<T>()` keep working. Routes that only need
to forward bytes can opt into a live stream with `StreamBody()`:

```csharp
app.Put("/upload/stream", Auth.RequireUser, async ctx =>
{
    // Peek at the magic bytes, then replay them into the storage stream.
    var check = await Files.CheckStreamAsync(ctx.Req.BodyStream, "image/*");
    if (!check.Ok)
        return check.ToError(ctx);

    var key = $"uploads/{Ids.New("file")}.{check.Extension}";
    await ctx.Storage.PutAsync(
        key,
        check.Body!,
        check.ContentType,
        new StoragePutOptions
        {
            CacheControl = "public, max-age=31536000, immutable",
        });

    return ctx.Json(new { key }, 201);
})
.StreamBody(maxBytes: 20_000_000);
```

- **Kestrel** hands the handler the live `HttpRequest.Body`; the body is never
  buffered by the framework. `StreamBody(maxBytes)` wraps it in a limit that
  returns 413 when exceeded.
- **Workers** still receive the body in the request envelope, but
  `ctx.Req.BodyStream` is a memory stream and the storage path reads it in
  parts instead of making another full copy.
- `StreamBody()` routes must not use `ctx.Req.Form`, `ctx.Req.Body`, or
  `ctx.BindJsonAsync<T>()`; those APIs need the buffered body.

Providers without `StreamingPut` fall back to buffering through the default
interface implementation.

## 7. Public URLs

Set a CDN/custom domain once and use `PublicUrl` for public assets:

```csharp
Storage = Storage.R2("https://cdn.example.com");

// or, on Native AOT:
Storage = Storage.S3(new S3StorageOptions
{
    Endpoint = "https://acc123.r2.cloudflarestorage.com",
    Bucket = "media",
    AccessKeyId = "...",
    SecretAccessKey = "...",
    PublicBaseUrl = "https://cdn.example.com",
});

var url = ctx.Storage.PublicUrl("avatars/user_1.png");
// https://cdn.example.com/avatars/user_1.png
```

`PublicUrl` returns null when the provider has no public base URL.

## 8. Metadata and listing

```csharp
var info = await ctx.Storage.HeadAsync(key);
// info.Size, info.ContentType, info.ETag, info.LastModified, info.Metadata

var page = await ctx.Storage.ListAsync(new StorageListOptions
{
    Prefix = $"avatars/{ctx.User!.Id}/",
    Limit = 50,
});

foreach (var item in page.Items)
{
    // item.Key, item.Size, item.ETag, item.LastModified
}

if (page.HasMore)
{
    var next = await ctx.Storage.ListAsync(new StorageListOptions
    {
        Prefix = $"avatars/{ctx.User!.Id}/",
        Cursor = page.Cursor,
        Limit = 50,
    });
}
```

On S3-compatible storage, listing uses `ListObjectsV2` with continuation tokens.
On R2, it uses the bucket's native cursor. On local disk, it walks the upload
root in ordinal key order.

## 9. Error mapping

Storage failures throw `StorageException` with a `StorageErrorCode`. The built-in
HTTP helpers map them to:

| Code | HTTP |
| :-- | :-- |
| `NotFound` | 404 |
| `InvalidKey` | 400 |
| `Unauthorized` / `Forbidden` | 403 |
| `PreconditionFailed` | 412 |
| `Conflict` | 409 |
| `TooLarge` | 413 |
| `RangeNotSatisfiable` | 416 |
| `Unsupported` | 501 |
| `Unavailable` | 503 |

`c.File` performs this mapping for you. For custom routes, catch
`StorageException` and return the matching status, or let the framework's
`internal_error` path handle genuinely unexpected failures.
