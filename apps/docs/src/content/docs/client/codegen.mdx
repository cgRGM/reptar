## Generated Artifacts

`bun reptar codegen` inspects the shared C# feature slices and outputs:

```text
examples/blog/rpc/
  app-type.d.ts           # Complete route tree type: AppType
  types.ts                # TypeScript DTO interfaces from C# records
  openapi.json            # OpenAPI 3.1 specification

packages/rpc/src/
  app-type.ts             # Synced copy used by @reptar/client
  types.ts                # Synced copy of generated DTOs

packages/rpc/
  openapi.json            # Synced OpenAPI document
```

The same `examples/blog` route/schema files compile into both the `net10.0` portable app and the `netwasm0.1` Worker, so the generated contract is based on the same routes that run on the edge.

## Consuming the Typed Client

The `@reptar/client` package provides a minimal (~100 lines), zero-dependency proxy client that provides full type inference for route segments, URL parameters, query strings, and request/response bodies:

```typescript
import { createClient } from "@reptar/client";
import type { AppType } from "./app-type";

// 1. Browser Client (includes cookies across requests)
export const api = createClient<AppType>(
  "https://reptar-api.rocktown-labs.workers.dev",
  {
    credentials: "include",
  }
);

// Calling endpoints with full autocomplete:
const postsResponse = await api.posts.$get();
if (postsResponse.ok) {
  const posts = await postsResponse.json(); // Typed as Post[]
}

// 2. Server-Side Rendering via Cloudflare Worker Service Binding (Zero Network Overhead)
export const ssrApi = createClient<AppType>("http://internal", {
  fetch: env.API.fetch.bind(env.API),
});
```

## Standard Schema (planned)

The current codegen emits `AppType`, DTO interfaces, and OpenAPI. Emitting `~standard` validators directly from `Rule<T>` is the next codegen milestone; until then, use the C# validators on the server and share the generated TypeScript types with your form library.
