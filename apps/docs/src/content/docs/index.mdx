**Reptar is the backend. Full stop.**

One compiled C# app — schema, routes, auth, validation, storage, streaming, agents — that runs identically as a **10.4 MB Native AOT container** on any VPS or in AWS Lambda, and as **WebAssembly** inside Cloudflare Workers. Zero runtime reflection: everything is resolved at compile time, which makes it fast, small, and _surprisingly good at being built by AI agents_.

```csharp
var app = ReptarApp.Create(new ReptarConfig
{
    Auth = BuiltIn(),
    Database = Db.Sqlite("app.db"),
});

app.Use(Telemetry());
app.Get("/api/notes", async c =>
{
    var notes = await c.Db.From<NoteRow>(Schema.Notes)
        .Where(Schema.NotesCols.UserId.Eq(c.User!.Id))
        .OrderBy(Schema.NotesCols.CreatedAt.Desc())
        .Limit(50)
        .ToListAsync();
    return c.Json(notes);
});

await app.EnsureCreatedAsync();
await app.RunAsync(args);
```

## Why it's fast (receipts, not adjectives)

  <Card title="41.9k req/s" icon="rocket">

    Built-in stale-while-revalidate caching, SQLite group-commit write batching

    VPS · Docker · AWS Lambda · Cloudflare Workers — same schema files, same

## Why you'll build with it

<CardGrid>
  <Card title="Batteries, compiled in" icon="battery">
    Sessions + OAuth + API keys, Stripe checkout & webhook verification, SSE/WebSockets, R2/local storage, rate limiting, SWR cache, OpenAPI 3.1 + Scalar — one binary, zero external auth services.
  </Card>
  <Card title="The compiler is your reviewer" icon="shield-check">
    Generated `ColumnRef` tokens make schema typos compile errors. `Rule<T>` is one source of truth for request validation, OpenAPI schemas, **and** LLM structured-output prompts.
  </Card>
  <Card title="Typed frontend, no glue" icon="check">
    TypeScript RPC clients, DTOs, and `~standard` validators regenerate from the C# route tree — `client.api.notes.$get()` with full autocomplete.
  </Card>
  <Card title="Agentic from first principles" icon="open-book">
    `llms.txt` as a rules-first reference, live schema/route inspection via JSON CLIs and MCP, and a built-in agent harness: modules, plan/execute modes, human-in-the-loop request ports, tool approvals, and evals.
  </Card>
</CardGrid>
