## Overview

Reptar provides two complementary ways to manage database schemas across SQLite, Cloudflare D1, PostgreSQL, and MySQL—with zero external ORM dependencies:

1. **CLI SQL Migration Runner (`bun scripts/reptar.ts db`)**: Scaffolds, inspects, and transactionally executes `.sql` migration files in `<1 ms` using Bun's native SQLite engine or D1.
2. **Programmatic C# `MigrationRunner`**: Tracks applied migrations in the `__reptar_migrations` table across SQLite, PostgreSQL, and MySQL with up/down rollback support.

## 1. CLI Migration Workflow

### Check Migration Status

View applied and pending `.sql` migrations in `migrations/`:

```bash
bun scripts/reptar.ts db status
```

### Scaffold a New Migration

Create the next sequential timestamped `.sql` migration file:

```bash
bun scripts/reptar.ts db new add_tasks_index
```

### Apply Pending Migrations

Run all unapplied migrations inside a single atomic transaction:

```bash
bun scripts/reptar.ts db migrate
```

## 2. Programmatic C# Migrations (`Migrations.cs`)

You can register migrations directly on `ReptarApp` in C# or load `.sql` files from a directory at startup:

```csharp
var app = ReptarApp.Create(new ReptarConfig
{
    Database = Db.Sqlite("app.db"), // Works identically on Postgres & MySQL
});

app.AddMigration(
    id: "001_initial_schema",
    upSql: """
        CREATE TABLE posts (
            id TEXT PRIMARY KEY,
            title TEXT NOT NULL,
            created_at TEXT NOT NULL
        );
        """,
    downSql: "DROP TABLE posts;");

// Apply all pending migrations idempotently
await app.MigrateAsync();

// Or roll back the most recent migration in tests/staging
await app.RollbackMigrationAsync(steps: 1);
```

### Loading `.sql` Files into `MigrationRunner`

You can also run directory-based migrations directly from your compiled Native AOT binary:

```csharp
var runner = await MigrationRunner.LoadFromDirectoryAsync(app.Db, "./migrations");
await MigrationRunner.RunCliAsync(runner, args); // Supports "migrate", "rollback", "status"
```

## 3. Compiler-Backed Schema Drift & DDL Generation

When defining tables with `TableDef` in `schema/`, Reptar extracts the exact compiled `SchemaRegistry.All` graph (`dotnet run -- --schema`) and diffs it against your active SQLite database (`pragma_table_info`):

- `bun reptar db plan [--json]` — Inspects schema drift (`create_table`, `add_column`, `create_index`) between your compiled C# `TableDef` declarations and the active SQLite database.
- `bun reptar db generate [--name <name>]` — Emits the next sequential timestamped `.sql` migration file in `migrations/` from the compiler-verified diff.
- `bun reptar db migrate` — Applies all pending `.sql` migrations transactionally.
