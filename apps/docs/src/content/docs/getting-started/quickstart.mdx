## What you're going to build

A production-shaped app with **real authentication**. When this page ends you will have:

Every step ends with a ✅ **checkpoint**. If a checkpoint fails, stop and fix it — the next step won't work.

<Aside type="note" title="Why the scaffold runs from the repo clone">
  The Reptar NuGet packages aren't published yet, so scaffolding builds your app
  file-based against the in-repo framework sources — the exact same `#:project`
  mechanism the framework's own examples use. Standalone `bun create reptar`
  scaffolds arrive with the 0.1 NuGet release; nothing else in this tutorial
  changes.
</Aside>

## 1. Create the app

```bash
git clone https://github.com/your-org/reptar.git   # or your fork
cd reptar
bun scripts/reptar.ts new my-app -y --db sqlite --auth better-auth
cd my-app
bun install
bun run dev
```

`bun run dev` starts both servers: the C# API at `http://localhost:8787` and the frontend at `http://localhost:5173` (the Vite dev server proxies `/api/*` to the backend).

✅ **Checkpoint: auth already works.** Open [http://localhost:5173](http://localhost:5173), click **Sign up**, and create an account. You're logged in — the session cookie was issued by your C# API (`POST /api/auth/sign-up/email`, Better Auth wire protocol). Sign out and sign back in. You just used the framework's built-in auth without configuring anything.

## 2. What you got (30 seconds)

```text
my-app/
├── apps/
│   ├── web/                      # React 19 + Vite — sign-up/dashboard wired up
│   │   └── src/lib/client.ts     # typed client (you'll regenerate it in step 5)
│   └── api/                      # your backend — a file-based C# app
│       ├── app.cs                # ~60 lines: config, middleware, feature mounts
│       ├── schema/schema.cs      # TableDefs — you'll edit this
│       └── features/            # one file per feature — you'll add one
├── packages/client/              # generated TypeScript contracts
└── deploy/                       # Dockerfile + compose + one-command deploy
```

You will only write C# in `schema/` and `features/`. Everything on the frontend is generated or already wired.

## 3. Define the notes table

Add to `apps/api/schema/schema.cs`:

```csharp
public static readonly TableDef Notes = DefineTable("notes",
    Col.Text("id").PrimaryKey(),
    Col.Text("user_id").NotNull().References("users", "id", onDelete: "cascade"),
    Col.Text("title").NotNull(),
    Col.Text("content").NotNull(),
    Col.Text("created_at").DefaultSql("CURRENT_TIMESTAMP")
);
```

<Aside type="tip" title="Why this looks like nothing">
  Storage schema is plain C# — no attributes, no fluent builders, no migration
  ceremony. The Reptar source generators read this declaration and emit typed
  `ColumnRef` tokens (`AppSchema.NotesCols.Title`) at compile time, and your
  table is created on the next boot.
</Aside>

## 4. Write the notes API

Create `apps/api/features/notes.cs`:

```csharp
namespace MyApp.Features;

using Reptar;
using MyApp.Schema;

public record NoteRow(string Id, string UserId, string Title, string Content, string CreatedAt);
public record CreateNoteInput(string Title, string Content);

public static class NotesFeature
{
    public static void Configure(ReptarApp app)
    {
        // Public feed — fluent query with generated ColumnRef tokens.
        app.Get("/api/notes", async ctx =>
        {
            var notes = await ctx.Db
                .From<NoteRow>(AppSchema.Notes)
                .OrderBy(AppSchema.NotesCols.CreatedAt.Desc())
                .Limit(50)
                .ToListAsync();

            return ctx.Json(notes);
        });

        // Authenticated write with Rule<T> validation.
        app.Post("/api/notes",
            ReptarApi.Rule<CreateNoteInput>()
                .Prop(x => x.Title, r => r.NotNull().Min(1).Max(120))
                .Prop(x => x.Content, r => r.NotNull().Min(1).Max(2000)),
            async (ctx, input) =>
            {
                var user = await ctx.UserAsync();
                if (user is null)
                    return ctx.Unauthorized();

                var note = new NoteRow(
                    Ids.New("note"),
                    user.Id,
                    input.Title,
                    input.Content,
                    DateTimeOffset.UtcNow.ToString("O"));

                await ctx.Db.InsertAsync(AppSchema.Notes, note);
                return ctx.Json(note, 201);
            })
            // One line exports this route to OpenAI/Anthropic/Gemini tool schemas.
            .AsAiTool("create_note", "Create a note for the signed-in user");
    }
}
```

Mount it in `app.cs` next to the other features, and register the table:

```csharp
NotesFeature.Configure(app);
app.RegisterSchema(AppSchema.Notes);
```

Restart `bun run dev` (the table is created automatically on boot).

✅ **Checkpoint: the API behaves like production.**

```bash
# No session → 401 (auth fires before anything else)
curl -i -X POST localhost:8787/api/notes \
  -H 'content-type: application/json' \
  -d '{"title":"hi","content":"first!"}' | head -1

# Sign up via the auth API and keep the session cookie
curl -s -c cookies.txt -X POST localhost:8787/api/auth/sign-up/email \
  -H 'content-type: application/json' \
  -d '{"email":"you@example.com","password":"supersecret123","name":"You"}'

# Signed-in write → 201, then the feed shows your note
curl -s -b cookies.txt -X POST localhost:8787/api/notes \
  -H 'content-type: application/json' \
  -d '{"title":"First note","content":"It works"}' -o /dev/null -w '%{http_code}\n'
curl -s localhost:8787/api/notes
```

An empty title gets a structured validation error — the same `Rule<T>` validators the generated frontend schemas are derived from.

## 5. Use it from the frontend

Regenerate the contracts — your C# routes just became TypeScript types:

```bash
bun run api:codegen
```

Open `apps/web/src/lib/client.ts` and you'll see the new routes in `AppType`. Fetch the feed anywhere in the frontend (autocomplete comes from the generated route tree):

```tsx
const res = await client.api.notes.$get();
if (res.ok) {
  const notes = await res.json();
}
```

✅ **Checkpoint:** post a note through the dashboard while signed in — it appears in the feed. In devtools: the session cookie rides along, and anonymous requests get 401. You have not written a single `fetch` or interface by hand.

## 6. Deploy it

The same C# app compiles to a **10.4 MB Native AOT container**. Take your pick:

<Tabs>
  <TabItem label="VPS / any Docker host">
    ```bash
    # on the server, from the repo clone:
    cd my-app/deploy
    bash deploy.sh
    ```
    The script builds the distroless image, starts compose (your app + PostgreSQL 17),
    and waits for the health check. Your SQLite `app.db` is fine for single-node;
    when you're ready, set `DATABASE_URL` to the compose Postgres (already wired).
  </TabItem>
  <TabItem label="Docker Compose">
    ```bash
    cd my-app/deploy
    docker compose up -d --build
    curl http://localhost:8787/health   # {"ok":true,...}
    ```
  </TabItem>
  <TabItem label="Cloudflare Workers">
    The scaffold ships a `wrangler.jsonc` with D1 bindings. The Workers pipeline
    (NetWasm publish + host shim) is documented in
    [Deployment Targets](/overview/deployment-targets/).
  </TabItem>
</Tabs>

✅ **Final checkpoint:** `curl http://your-server/health` returns `{"ok":true,...}` — then open the site and **create a real account on production**. Auth, validation, your notes API, and the health gate are live in a container smaller than most node_modules.
